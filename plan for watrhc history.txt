This new model will be designed from the ground up to support every feature you mentioned:

    Continue Watching: A simple query for items with a progress_seconds > 0 and watched_status set to in_progress.

    Watch History: A query for items where watched_status is watched.

    Playback Position & Smart Detection: The table will store progress_seconds and duration_seconds. We can implement backend logic where if progress_seconds is within, say, 95% of the duration_seconds, we automatically flag watched_status as watched.

    Watchlist/Tracking: A simple boolean flag (in_watchlist) will manage this.

    Calendar/Following: Another flag (tracked_for_release) will drive the notification and calendar features.

    Favorites: A flag like is_favorite.

    External Sync: Columns for trakt_id, imdb_id, etc., can be added later without refactoring the entire system.

    Profile Settings: This state will live separately but will influence how the profile_media_state is queried and updated.
